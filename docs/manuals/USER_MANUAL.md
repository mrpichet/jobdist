# คู่มือการใช้งาน JobDist (User Manual)

เวอร์ชัน 2.0 · ปรับปรุง 25 พฤศจิกายน 2569

JobDist คือระบบจัดคิวและกระจายงาน (Job) ไปยังเครื่องประมวลผล (Worker) หลายเครื่อง คู่มือนี้อธิบายการใช้งานเว็บคอนโซลสำหรับผู้ดูแลและผู้ใช้งาน

---

## 1. การเข้าสู่ระบบ

1. เปิดเว็บ JobDist (เช่น `https://jobdist.example.com`)
2. เลือก **ประเภทบัญชี** (บัญชีของระบบ, Active Directory หรือ LDAP ตามที่หน่วยงานเปิดใช้)
3. กรอก **ชื่อผู้ใช้** และ **รหัสผ่าน** แล้วกด **เข้าสู่ระบบ**
4. ถ้าบัญชีเปิด MFA ระบบจะถามรหัส 6 หลักจากแอป Authenticator
5. ถ้าระบบแจ้งว่าต้องเปลี่ยนรหัสผ่าน ให้เปลี่ยนก่อนใช้งาน

บัญชีและสิทธิ์ทั้งหมดจัดการใน AuthServer ถ้าเมนูหรือปุ่มที่ต้องการไม่แสดง แปลว่าบัญชียังไม่มีสิทธิ์นั้น ให้ติดต่อผู้ดูแล AuthServer (ดูตารางสิทธิ์ในหัวข้อ 10)

**แถบด้านบน** มีปุ่มเปลี่ยนภาษา (ไทย/อังกฤษ), โหมดสว่าง/มืด, ผู้ช่วย AI (ถ้าเปิดใช้) และเมนูผู้ใช้สำหรับ เปลี่ยนรหัสผ่าน, ตั้งค่าส่วนตัว, เกี่ยวกับระบบ และออกจากระบบ

ระบบจะออกจากระบบเองเมื่อ session หมดอายุ (ไม่ได้ใช้งาน 30 นาที หรือครบ 12 ชั่วโมง) หรือเมื่อผู้ดูแลยกเลิก session

## 2. โครงสร้างเมนู

| กลุ่ม | เมนู | ใช้ทำอะไร |
|---|---|---|
| ภาพรวม | ภาพรวมระบบ | ตัวเลขสำคัญ สถานะคิว และ Worker |
| งาน (Jobs) | รายการ Job, ส่ง Job ใหม่, ส่ง Job จากไฟล์ | ค้นหา ติดตาม ส่ง และจัดการงาน |
| Worker | รายการ Worker | ดูเครื่องประมวลผล, Drain, ถอดออก |
| วิเคราะห์ | ประสิทธิภาพและคำแนะนำ Worker, ความผิดปกติ (Anomaly), รายงานสถิติ Job | วิเคราะห์และรายงาน |
| การแจ้งเตือน | ประวัติการแจ้งเตือน, ผู้รับการแจ้งเตือน, เกณฑ์คิว | ตั้งค่าและตรวจสอบการแจ้งเตือนผ่าน MessageHub |

ทุกหน้ารายการรองรับการค้นหา เรียงลำดับ กรองตามคอลัมน์ และส่งออกเป็น Excel/CSV/PDF (ถ้ามีสิทธิ์ส่งออก) การสร้าง ดู และแก้ไขข้อมูลทำในหน้าแบบฟอร์มเต็มหน้า ถ้าออกจากหน้าแบบฟอร์มที่แก้ไขค้างไว้ ระบบจะถามยืนยันก่อน

## 3. ภาพรวมระบบ

- **ตัวเลขหลัก**: Worker ออนไลน์/กำลัง Drain/ออฟไลน์, กำลังการประมวลผลรวม, งานที่กำลังทำ และงานที่รอคิว กดการ์ดเพื่อเปิดหน้ารายการที่เกี่ยวข้อง (เช่น การ์ดงานที่รอคิวเปิดรายการงานสถานะรอคิว)
- **งานแยกตามสถานะ**
- **คิวที่รอ** แยกตามประเภท Job และ **สถานะเกณฑ์คิว** (ปกติ / ใกล้เต็ม / เกินเกณฑ์) พร้อมแถบแสดงเปอร์เซ็นต์
- **เครื่องหลัก (Leader)**: server ตัวที่ทำหน้าที่จัดคิวอยู่ในขณะนั้น
- **รีเฟรชอัตโนมัติ**: เลือก ปิด / 10 / 30 / 60 วินาที ระบบจำค่าไว้ในเบราว์เซอร์ของคุณ กดปุ่ม **รีเฟรช** เพื่อโหลดใหม่ทันทีได้เสมอ

## 4. งาน (Jobs)

### 4.1 สถานะของงาน

| สถานะ | ความหมาย |
|---|---|
| รอคิว (Pending) | รอจัดสรรให้ Worker (รวมงานที่ตั้งเวลาไว้และงานที่รอ retry) |
| จัดสรรแล้ว (Assigned) | ส่งให้ Worker แล้ว รอ Worker เริ่ม |
| กำลังทำ (Running) | Worker กำลังประมวลผล |
| สำเร็จ (Succeeded) | เสร็จเรียบร้อย (สถานะสุดท้าย) |
| ล้มเหลว (Failed) | ล้มเหลวครบจำนวนครั้งหรือผิดพลาดแบบไม่ลองใหม่ (สถานะสุดท้าย) |
| กำลังยกเลิก (CancelRequested) | สั่งยกเลิกแล้ว รอ Worker หยุดงาน |
| ยกเลิกแล้ว (Cancelled) | ยกเลิกเรียบร้อย (สถานะสุดท้าย) |

### 4.2 รายการ Job
กรองตามสถานะ ประเภท Job หรือ Worker ได้ คลิกที่แถวเพื่อเปิดรายละเอียด ระบบแสดงงานใหม่สุดก่อน

### 4.3 ส่ง Job ใหม่
1. เลือก **ประเภท Job** (รายการมาจาก Worker ที่ออนไลน์และงานที่ค้างในคิว)
2. ใส่ **Payload** เป็น JSON (ไม่เกิน 1 MB) และ **Priority** 0–100 (ค่าเริ่มต้น 50, ยิ่งมากยิ่งทำก่อน)
3. ตัวเลือกเพิ่มเติม: Worker ที่ต้องการ (และ **บังคับเฉพาะ Worker** นี้), จำนวนครั้งสูงสุด (1–20), Timeout (วินาที), เวลาเริ่มรัน, Tags (ไม่เกิน 10), **ข้อมูลอ่อนไหว** (Payload จะถูกเข้ารหัสถึง Worker)
4. กด **ประเมินความเสี่ยง** เพื่อดูคะแนนความเสี่ยง (0–100) พร้อมเหตุผล เช่น ไม่มี Worker ที่รองรับ หรือคิวยาว ระบบไม่สร้างงานในขั้นนี้
5. กด **ส่ง Job** ระบบป้องกันการส่งซ้ำเมื่อกดซ้ำหรือเครือข่ายขัดข้อง

ถ้าขึ้นข้อความ **"คิวเต็ม ระบบไม่รับงานใหม่"** แปลว่างานประเภทนี้มีงานรอเกินเกณฑ์คิวที่ตั้งไว้ ระบบจะแจ้งจำนวนที่รออยู่และเกณฑ์สูงสุด ให้รอสักครู่ (ประมาณ 1 นาที) แล้วส่งใหม่ หรือติดต่อผู้ดูแลเพื่อเพิ่ม Worker หรือปรับเกณฑ์

### 4.4 รายละเอียด Job
แสดงข้อมูลทั้งหมดของงาน ผลลัพธ์หรือข้อผิดพลาดล่าสุด, **ประวัติการทำงาน** ทุกครั้ง (Worker, เวลารอคิว, เวลาทำงาน, ผล) และ **ความเสี่ยง** ของงาน ข้อมูลแสดงเป็นช่องอ่านอย่างเดียว ส่วนตารางในหน้านี้ค้นหา กรอง เรียง และเลือกคอลัมน์ได้เหมือนหน้ารายการ จากหน้านี้ไปที่ **เปลี่ยน Priority** หรือ **ยกเลิก** ได้ (เฉพาะงานที่ยังไม่จบ)

### 4.5 เปลี่ยน Priority / ยกเลิก Job
- **เปลี่ยน Priority**: ใส่ค่าใหม่ 0–100 แล้วบันทึก มีผลกับงานที่ยังรอคิว
- **ยกเลิก**: ใส่เหตุผล (ไม่บังคับ) แล้วยืนยัน ถ้า Worker กำลังทำงานนี้อยู่ สถานะจะเป็น "กำลังยกเลิก" จนกว่า Worker จะหยุด

### 4.6 ส่ง Job จากไฟล์
1. กด **ดาวน์โหลดแม่แบบ** (Excel หรือ CSV)
2. กรอกหนึ่งแถวต่อหนึ่งงาน คอลัมน์: ประเภท Job (บังคับ), Payload (JSON), Priority, Worker ID ที่ต้องการ, บังคับเฉพาะ Worker, จำนวนครั้งสูงสุด, Timeout (วินาที), เวลาเริ่มรัน (`yyyy-MM-dd HH:mm` หรือ `dd/MM/yyyy HH:mm`), Idempotency key, ข้อมูลอ่อนไหว, Tags (คั่นด้วยจุลภาค) หัวคอลัมน์ใช้ภาษาไทยหรืออังกฤษก็ได้
3. อัปโหลดไฟล์ ระบบตรวจทุกแถวและแสดงแถวที่ผิดพร้อมสาเหตุ แก้ไขให้ครบก่อนนำเข้า
4. กด **นำเข้า** ระบบส่งทั้งไฟล์ในครั้งเดียว (ไม่เกิน 5,000 แถว) ถ้าคิวเต็ม จะไม่รับทั้งชุด

การนำเข้าไฟล์เดิมซ้ำจะไม่สร้างงานซ้ำ ระบบตรวจจากเนื้อหาไฟล์และลำดับแถว

## 5. Worker

### 5.1 สถานะของ Worker
| สถานะ | ความหมาย |
|---|---|
| ออนไลน์ (Online) | พร้อมรับงาน |
| กำลัง Drain (Draining) | ไม่รับงานใหม่ ทำงานที่ค้างให้เสร็จ |
| ออฟไลน์ (Offline) | ขาดการติดต่อ งานที่ถืออยู่ถูกกระจายใหม่ |
| ถอดออกแล้ว (Unregistered) | ออกจากระบบแล้ว |

### 5.2 รายการและรายละเอียด Worker
แสดง CPU/หน่วยความจำ, งานที่ทำอยู่เทียบกับความจุ, ประเภทงานที่รองรับ, สเปกเครื่อง, เวอร์ชัน, การรองรับการเข้ารหัสแบบ PQC และ **ความเสี่ยง** ของ Worker (เช่น ออฟไลน์บ่อย อัตราล้มเหลวสูง) เลือก "แสดง Worker ที่ถอดออกแล้ว" เพื่อดูย้อนหลัง

### 5.3 Drain Worker
ใช้ก่อนปิดเครื่องเพื่อบำรุงรักษา Worker จะไม่รับงานใหม่และทำงานที่ค้างให้เสร็จ หน้ายืนยันจะแสดงจำนวนงานที่ค้างอยู่

### 5.4 ถอด Worker ออกจากระบบ
ใช้กับเครื่องที่เลิกใช้หรือค้าง งานที่ Worker ถืออยู่จะถูกกระจายไปเครื่องอื่นทันที ระบบส่งแจ้งเตือน "Worker ถูกถอดออก" ให้ผู้รับที่สมัครไว้

## 6. วิเคราะห์

### 6.1 ประสิทธิภาพและคำแนะนำ Worker
- ตารางและกราฟเวลาทำงานเฉลี่ย ส่วนเบี่ยงเบน จำนวนสำเร็จ/ล้มเหลว แยกตาม Worker และประเภท Job
- เลือกประเภท Job แล้วดู **Worker ที่แนะนำ** พร้อมคะแนน ภาระงาน เวลาที่คาด โอกาสสำเร็จ และเหตุผล

### 6.2 ความผิดปกติ (Anomaly)
เลือกช่วงเวลา (5–1,440 นาที) ระบบตรวจ เช่น งานเข้ามากผิดปกติ อัตราล้มเหลวสูง งานช้า Worker หลุดเข้าออกบ่อย คิวค้างไม่มี Worker รับ การย้ายงานจำนวนมาก และพฤติกรรม Worker ที่น่าสงสัย ระดับความรุนแรงมี ข้อมูล / เตือน / วิกฤต

ระบบตรวจอัตโนมัติทุกนาทีและส่งแจ้งเตือนเอง (ไม่ส่งซ้ำเรื่องเดิมภายใน 30 นาที) ปุ่ม **ส่งแจ้งเตือนตอนนี้** ใช้ส่งผลที่เห็นทันที (ต้องมีสิทธิ์ส่งแจ้งเตือน)

### 6.3 รายงานสถิติ Job
1. เลือกช่วงวันที่ (ไม่เกินระยะเก็บข้อมูล ค่าเริ่มต้น 30 วัน) ประเภท Job หรือ Worker (ไม่บังคับ)
2. เลือกการจัดกลุ่ม: รายวัน, ตามประเภท Job, ตาม Worker หรือหลายแบบรวมกัน
3. กด **แสดงรายงาน** แล้วส่งออกเป็น Excel/PDF ได้

| ค่า | วิธีคิด |
|---|---|
| อัตราสำเร็จ | สำเร็จ ÷ (สำเร็จ + ล้มเหลว) × 100 (ไม่นับงานที่ยกเลิก) |
| จำนวนครั้งเฉลี่ย | ครั้งที่ทำ ÷ งานที่จบแล้ว |
| เวลาทำงานเฉลี่ย / P95 | คิดจากการทำงานที่สำเร็จเท่านั้น P95 คลาดเคลื่อนได้ประมาณ ±5% |
| เวลารอคิวเฉลี่ย | จากเวลาสร้าง/ถึงกำหนดจนถึงจัดสรรให้ Worker |
| Throughput | งานที่สำเร็จต่อชั่วโมง |

วันในรายงานใช้เวลาประเทศไทย (Asia/Bangkok)

## 7. การแจ้งเตือน

ระบบส่งแจ้งเตือนผ่าน MessageHub (เช่น อีเมล, Teams, LINE ตามช่องทางที่ MessageHub เปิดไว้) เมื่อเกิดเหตุการณ์ต่อไปนี้

| เหตุการณ์ | เมื่อไร |
|---|---|
| พบความผิดปกติ | การตรวจอัตโนมัติพบ Anomaly ระดับ "เตือน" ขึ้นไป |
| Worker ลงทะเบียน | Worker เข้าระบบหรือกลับเข้ามาใหม่ |
| Worker ถูกถอดออก | ถอดออกจากระบบ |
| Worker หายไป | ขาดการติดต่อโดยไม่ได้ถอดออก |
| เปลี่ยนเครื่องหลัก | server ตัวที่เป็น Leader เปลี่ยน |
| คิวใกล้เต็ม | งานรอถึงเปอร์เซ็นต์เตือนของเกณฑ์คิว |
| คิวเกินเกณฑ์ | มีงานใหม่ถูกปฏิเสธเพราะเกินเกณฑ์ |
| ทดสอบ | กดส่งทดสอบจากหน้าผู้รับ |

### 7.1 ผู้รับการแจ้งเตือน
- **เพิ่มผู้รับ**: ชื่อ, ช่องทาง, ที่อยู่ (อีเมล/ID ตามช่องทาง), เหตุการณ์ที่ต้องการรับ (อย่างน้อย 1), ระดับความรุนแรงขั้นต่ำ, เปิด/ปิดใช้งาน
- ที่อยู่ถูกเข้ารหัสเก็บในฐานข้อมูลและแสดงแบบปิดบางส่วนเท่านั้น เมื่อแก้ไข ถ้าเว้นช่องที่อยู่ว่างไว้ ระบบจะใช้ที่อยู่เดิม
- **ส่งทดสอบ**: ส่งข้อความทดสอบทันทีและแสดงผล
- ถ้ามีคนอื่นบันทึกข้อมูลเดียวกันก่อน ระบบจะแจ้งให้โหลดใหม่แล้วแก้อีกครั้ง

### 7.2 เกณฑ์คิว
- กำหนดต่อประเภท Job หรือ `*` (ทุกประเภทรวมกัน): **จำนวนงานรอสูงสุด** และ **เปอร์เซ็นต์เตือน** (ค่าเริ่มต้น 80%)
- ถึงเปอร์เซ็นต์เตือน: ส่งแจ้งเตือน "คิวใกล้เต็ม"
- งานใหม่ทำให้เกินจำนวนสูงสุด: ระบบ **ปฏิเสธงานนั้น** และส่งแจ้งเตือน "คิวเกินเกณฑ์"
- แจ้งเตือนเรื่องเดียวกันซ้ำไม่เกินทุก 30 นาทีระหว่างที่ยังเกินอยู่
- ปิดเกณฑ์ (ไม่เลือก "เปิดใช้งาน") เพื่อหยุดตรวจชั่วคราวโดยไม่ลบ

### 7.3 ประวัติการแจ้งเตือน
แสดงทุกข้อความที่ส่งหรือพยายามส่ง: เวลา, เหตุการณ์, ระดับ, หัวข้อ, ผู้รับ (ที่อยู่แบบปิดบาง), สถานะ และจำนวนครั้งที่ลอง

| สถานะ | ความหมาย |
|---|---|
| รอส่ง (Pending) | รอส่งหรือรอลองใหม่ (ระบบลองใหม่อัตโนมัติ โดยเว้นระยะห่างขึ้นเรื่อย ๆ) |
| ส่งแล้ว (Sent) | MessageHub รับข้อความแล้ว |
| ล้มเหลว (Failed) | ข้อผิดพลาดถาวร หรือครบจำนวนครั้งที่ลอง (ค่าเริ่มต้น 10) |
| ข้าม (Skipped) | ไม่มีผู้รับที่สมัครเหตุการณ์นี้, ผู้รับถูกปิด/ลบ หรือยังไม่ได้ตั้งค่า MessageHub |

## 8. ผู้ช่วย AI

ถ้าผู้ติดตั้งเปิดใช้ จะมีปุ่มผู้ช่วย AI ที่แถบด้านบน ถามเป็นภาษาไทยหรืออังกฤษได้ เช่น "สรุปสถานะระบบตอนนี้" หรือ "Worker ตัวไหนเหมาะกับงาน image.resize" ผู้ช่วยอ่านข้อมูลได้อย่างเดียว ไม่ส่ง ยกเลิก หรือแก้ไขงาน และเห็นเฉพาะข้อมูลที่บัญชีของคุณมีสิทธิ์ **อย่าพิมพ์รหัสผ่านหรือข้อมูลส่วนบุคคล** เพราะข้อความถูกส่งไปยังบริการ AI ภายนอก

## 9. ปัญหาที่พบบ่อย

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| เข้าสู่ระบบไม่ได้ | ตรวจประเภทบัญชี ชื่อผู้ใช้ รหัสผ่าน หรือบัญชีถูกล็อก ติดต่อผู้ดูแล AuthServer |
| ไม่เห็นเมนู/ปุ่ม | บัญชียังไม่มีสิทธิ์ ดูหัวข้อ 10 |
| "คิวเต็ม" ตอนส่งงาน | งานรอเกินเกณฑ์คิว รอแล้วส่งใหม่ หรือแจ้งผู้ดูแล |
| ถูกออกจากระบบเอง | session หมดอายุหรือถูกยกเลิก เข้าสู่ระบบใหม่ |
| แจ้งเตือนไม่มาถึง | ดูหน้าประวัติการแจ้งเตือน: Skipped = ไม่มีผู้รับ/ยังไม่ตั้งค่า MessageHub, Failed = ดูข้อความผิดพลาด |
| บันทึกไม่ได้ ระบบแจ้งว่ามีคนแก้ไขก่อน | โหลดหน้าใหม่แล้วแก้ไขอีกครั้ง |

## 10. สิทธิ์การใช้งาน

สิทธิ์อยู่ใน Application `jobdist` ของ AuthServer ผู้ที่มีบทบาท `admin` ของ AuthServer ใช้ได้ทุกเมนู

| สิทธิ์ | ใช้กับ |
|---|---|
| `jobdist.dashboard.view` | ภาพรวมระบบ, สถานะคิว |
| `jobdist.job.view` | รายการ/รายละเอียด Job, ความเสี่ยงของ Job |
| `jobdist.job.create` | ส่ง Job ใหม่, ส่งจากไฟล์, ประเมินความเสี่ยงก่อนส่ง |
| `jobdist.job.edit` | เปลี่ยน Priority |
| `jobdist.job.cancel` | ยกเลิก Job |
| `jobdist.job.export` | ส่งออกรายการ Job เป็นไฟล์ (หน้าอื่นส่งออกได้เมื่อมีสิทธิ์ดูหน้านั้น) |
| `jobdist.worker.view` | รายการ/รายละเอียด Worker |
| `jobdist.worker.drain` | Drain Worker |
| `jobdist.worker.unregister` | ถอด Worker ออก |
| `jobdist.insight.view` | ประสิทธิภาพ คำแนะนำ และความผิดปกติ |
| `jobdist.alert.send` | ส่งแจ้งเตือนความผิดปกติทันที |
| `jobdist.alert.view` | ประวัติการแจ้งเตือน, ดูผู้รับและเกณฑ์คิว |
| `jobdist.alert.manage` | เพิ่ม/แก้/ลบ/ทดสอบผู้รับ |
| `jobdist.queue.manage` | เพิ่ม/แก้/ลบเกณฑ์คิว |
| `jobdist.report.view` | รายงานสถิติ Job |
| `jobdist.agent.use` | ผู้ช่วย AI |

ตัวอย่างการจัดบทบาท: **ผู้ดูงาน** = dashboard.view, job.view, worker.view, insight.view, report.view · **ผู้ส่งงาน** = ผู้ดูงาน + job.create, job.edit, job.cancel · **ผู้ดูแลระบบงาน** = ทุกสิทธิ์
