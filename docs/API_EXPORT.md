# JobDist API export

> Generated by `tools/JobDist.ApiExport` from the compiled assemblies and XML doc comments. Do not edit by hand:
> run `dotnet run --project tools/JobDist.ApiExport -- docs` after changing the API. Machine-readable copy: `api-export.json`.

JobDist is a distributed job scheduler. The same business logic is served as a **REST API** (`/api/*`) and as an **MCP server** (`/mcp`, tools built with Microsoft.Extensions.AI).

## Authentication

- Machines (workers, SDK, MCP, scripts): header `X-Api-Key: <key>`. Keys map to roles **Admin, Submitter, Viewer, Worker, AiAgent** (only SHA-256 hashes are stored server-side).
- People (web console): `Authorization: Bearer <access token>` from AuthServer (Application `jobdist`); access needs the `jobdist.*` permission shown in the Auth column, or the AuthServer admin role.
- Auth column "permission `p` / API key S": a Bearer token passes with permission `p`, an API key passes with a role of set S (Read = Viewer/Submitter/Admin, Submit = Submitter/Admin, Admin, WorkerOrAdmin, ConsoleRead = Admin in Production else Viewer/Submitter/Admin, ConsoleWrite = Admin, None = no API key).
- Versioning: routes are `api/v1/...`; the unversioned `api/...` alias is the same v1 endpoint (header `api-version` or `?api-version=1.0` also accepted).
- POST endpoints marked idempotent accept `Idempotency-Key` (1-100 chars): a retry with the same body replays the first response (header `Idempotent-Replayed: true`), a different body gets 422.
- Worker calls (`/api/workers/{workerId}/...`): also `X-Worker-Token: <token>` returned once by `POST /api/workers/register`.
- Enums are serialized as strings (e.g. `"Pending"`). Times are ISO-8601 UTC. Errors are RFC 7807 problem details; 429 with `error: queue_full` and `Retry-After` when a queue threshold is exceeded.

## MCP / AI tools

Endpoint `POST /mcp` (Streamable HTTP, stateless), API key with role **AiAgent**; or the stdio host `src/JobDist.McpServer`.
Side-effect tools are only listed when the server sets `Mcp:AllowSideEffects=true`.

### `assess_job_risk`

Calculate the risk (0-100) that a job fails, is delayed or is lost: no capable/online worker, strict target offline, backlog vs capacity, historical failure rate, expected duration vs timeout, attempts already used, unstable assigned worker. Returns score, level, factors and a recommendation.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `jobId` | string | yes | Job id (GUID). |

### `assess_submission_risk`

What-if: calculate the risk (0-100) of submitting a job of the given type BEFORE creating it (capability, redundancy, backlog, history, timeout, encryption keys for sensitive payloads). Nothing is created.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `jobType` | string | yes | Job type, e.g. 'image.resize'. |
| `targetWorkerId` | ["string","null"] | no | Optional worker id (GUID) that should run the job. |
| `strictTarget` | boolean | no | true = run only on targetWorkerId. |
| `timeoutSeconds` | ["integer","null"] | no | Timeout per attempt in seconds (null = server default). |
| `sensitive` | boolean | no | true when the payload is confidential (needs encrypted delivery). |

### `assess_worker_risk`

Calculate the health risk (0-100) of a worker: availability, network instability (offline count), learned failure rate per job type, CPU/memory pressure and missing post-quantum keys.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `workerId` | string | yes | Worker id (GUID). |

### `detect_anomalies`

Detect abnormal job distribution in a recent window: submission spikes (z-score), high failure rates per job type or worker, slow execution, flapping workers, fail-over storms, queues without capable workers and suspicious worker reports.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `windowMinutes` | integer | no | Window size in minutes (5-1440). |

### `recommend_workers`

Rank online workers for a job type with the scheduler's own scoring (load, ML-predicted speed and reliability, exploration). Explains why each worker is ranked.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `jobType` | string | yes | Job type. |
| `top` | integer | no | Max results (1-100). |

### `get_job_status`

Get the status of a job: state, priority, assigned worker, attempts, timings, result or last error.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `jobId` | string | yes | Job id (GUID). |

### `list_jobs`

List recent jobs, optionally filtered by status (Pending, Assigned, Running, Succeeded, Failed, CancelRequested, Cancelled) and job type.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `status` | ["string","null"] | no | Optional status filter. |
| `jobType` | ["string","null"] | no | Optional job type filter. |
| `take` | integer | no | Max results (1-200). |

### `get_job_history`

Get the distribution history of a job: every attempt with worker, queue wait, duration, outcome and scheduler score.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `jobId` | string | yes | Job id (GUID). |

### `list_workers`

List registered workers with status, capabilities (job types and concurrency), machine spec, current load and stability.

### `get_cluster_summary`

Get a cluster overview: workers online/draining/offline, capacity, jobs by status, pending jobs per type and the current HA leader.

### `get_worker_performance`

Get what the ML model learned about worker performance per job type: samples, success/failure counts, mean and standard deviation of duration.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `jobType` | ["string","null"] | no | Optional job type filter. |

### `get_queue_status`

Get pending jobs compared with the configured queue thresholds: pending, limit, usage percent and level (Normal, NearLimit, OverLimit). Over the limit, new jobs of that type are rejected.

### `list_alert_logs`

List alerts sent to administrators through MessageHub in the last hours: event type, severity, title, recipient (masked address) and delivery status.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `hours` | integer | no | Look back this many hours (1-720). |
| `eventType` | ["string","null"] | no | Optional event type: AnomalyDetected, WorkerRegistered, WorkerUnregistered, WorkerLost, LeaderChanged, QueueNearLimit, QueueOverLimit, Test. |

### `get_job_statistics`

Job statistics per day (Asia/Bangkok), job type or worker: submitted, succeeded, failed, cancelled, success rate, average attempts, average and P95 duration, average queue wait, throughput per hour. Dates are yyyy-MM-dd; range at most the retention period (30 days).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `fromDate` | string | yes | First day, yyyy-MM-dd. |
| `toDate` | string | yes | Last day, yyyy-MM-dd. |
| `jobType` | ["string","null"] | no | Optional job type filter. |
| `groupBy` | string | no | Grouping: day, jobType, worker or a comma-separated combination. |

| Parameter | Type | Required | Description |

| `reason` | ["string","null"] | no | Reason recorded on the job. |

### `change_job_priority` (side effect)

Change the priority (0-100) of a job that has not finished. Only available when side-effect tools are enabled.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `jobId` | string | yes | Job id (GUID). |
| `priority` | integer | yes | New priority 0-100. |

## SDKs

- **Submit jobs** from another project: reference `JobDist.Client`, `services.AddJobDistClient(configuration.GetSection("JobDistClient"))`, inject `IJobDistClient`.
- **Implement a worker**: reference `JobDist.Worker.Sdk`, implement `IJobHandler`, `services.AddJobDistWorker(configuration).AddJobHandler<MyHandler>()` (section `JobDistWorker`).

### `IJobDistClient` (interface)

Job submission API for other projects.

| Member | Type | Description |
|---|---|---|
| `SubmitAsync(SubmitJobRequest request, CancellationToken ct)` | Task<SubmitJobResponse> | Submits a job. An idempotency key is generated when missing so automatic fail-over retries never duplicate the job. |
| `SubmitBatchAsync(IReadOnlyList<SubmitJobRequest> jobs, CancellationToken ct)` | Task<IReadOnlyList<SubmitJobResponse>> | Submits up to 5,000 jobs in one call. |
| `GetAsync(Guid jobId, CancellationToken ct)` | Task<JobStatusResponse> | Gets a job's status. |
| `ListAsync(JobStatus? status, string jobType, int skip, int take, CancellationToken ct)` | Task<PagedResponse<JobStatusResponse>> | Lists jobs. |
| `GetAttemptsAsync(Guid jobId, CancellationToken ct)` | Task<IReadOnlyList<JobAttemptResponse>> | Distribution history of a job. |
| `ChangePriorityAsync(Guid jobId, int priority, CancellationToken ct)` | Task<JobStatusResponse> | Changes the priority of an unfinished job (0-100). |
| `CancelAsync(Guid jobId, string reason, CancellationToken ct)` | Task<JobStatusResponse> | Cancels a job (the server tells the worker to stop). |
| `WaitForCompletionAsync(Guid jobId, TimeSpan? pollInterval, CancellationToken ct)` | Task<JobStatusResponse> | Polls until the job reaches a final state (Succeeded / Failed / Cancelled) or the token is cancelled. |
